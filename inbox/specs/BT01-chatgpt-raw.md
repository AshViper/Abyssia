- 建設物単位で解体する。

- 解体時間は 20 tick。
- 解体中断時には何も返却しない。
- 完了時に80%素材をプレイヤーへ返却する。
- インベントリに入り切らない場合は、余剰素材を解体地点にドロップする。

- 建設装置から建設済みモジュールを選択して解体できる。
- モジュール全体が一括で解体される。
- 返却量が元コストの80%になる。
- 隣接モジュールを巻き込まない。
- 通常ブロックを誤って解体しない。
- 解体で開口部が発生した場合に浸水状態が正しく更新される。
- 拠点分断後もサーバー再起動を挟んで拠点情報が破綻しない。

# BT01d マルチブロック発電機

tier: heavy

files:
- 海流発電機本体・マルチブロック判定
- 地熱発電機本体・マルチブロック判定
- バイオ燃料発電機本体・マルチブロック判定
- 3種の発電処理・FE生成処理
- 発電機のモデル・レンダリング関連ファイル

goal:
- 海流・地熱・バイオ燃料の3種類の大型発電設備を建設装置から設置できるようにする。

共通仕様:
- すべてマルチブロック設備。
- 建設装置から「基部」を設置すると必要ブロックが自動生成される。
- 設備は1つの建設単位として扱う。
- 解体時は BT01b の解体処理に従う。
- 立方体1ブロックだけの機械にはしない。
- 立体的な工業設備として表示する。
- 発電した FE は既存の「拠点共有 1,000,000 FE」に直接送る。
- ケーブルを発電機へ接続する必要はない。
- 拠点外へ直接 FE を送らない。
- 発電設備が拠点外に単独設置されている場合は発電しない。
- 拠点内の設備からのみ共有電力へ供給する。

### 海流発電機

寸法:
- 5x5x5

設置:
- 拠点外壁から海側へ突出する位置。
- 完成時のタービン部分が海中にあること。
- 海流を取得できる位置であること。

発電:
- getCurrentAt(pos) の海流強度を使用。
- 基準値: 海流強度 1.0 で 120 FE/t。
- 発電量 = 120 × 海流強度。
- 0.1 未満では停止。
- 上限 240 FE/t。
- 海流の強さに応じてタービン回転速度を変更する。

### 地熱発電機

寸法:
- 3x3x4

設置:
- 天然の熱水噴出孔の真上。
- 地熱発電機の発電部が噴出孔と正しく一致する必要がある。
- 噴出孔以外では発電しない。

発電:
- 既存熱水発電機の活動度を利用する。
- 活動度0: 0 FE/t
- 活動度1: 80 FE/t
- 活動度2: 160 FE/t
- 既存の熱水発電機ロジックと矛盾する別の噴出孔判定を作らない。

### バイオ燃料発電機

寸法:
- 3x3x3

燃料:
- 生体油昆布由来の既存「生体油」を燃料として使用する。
- 新規燃料アイテムは追加しない。
- 1,000 mB 相当の生体油で 100,000 FE。
- 消費速度は 100 FE/t。
- したがって満タン相当で 1,000 tick 発電する。
- 発電中は燃料を自動消費する。
- 燃料が無くなれば停止。

accept:
- 3種類すべて建設装置から建設できる。
- マルチブロックが正しく完成する。
- 条件を満たさない場合は発電しない。
- 発電量が指定値になる。
- 3種類とも拠点共有 FE に直接供給される。
- ケーブルなしで拠点設備が電力を利用できる。
- 解体時に1設備として処理される。
- モデルが単純な1立方体ではなく、各発電方式を視覚的に識別できる。

- 捕獲可能なのは以下。
  - 深海魚
  - 深海ウナギ
  - 深海サメ
  - 深海クラゲ
- ボス・敵対Mob・大型特殊Mobは対象外。
- 生物の種類をNBTへ保存。

- 水槽から直接アイテムとして魚を取り出す機能は付けない。
- 水槽を解体した場合、中の生物は消滅させず、捕獲容器へ変換してドロップする。

## 建設コスト

既存設備については既存クラフトレシピの材料をそのまま建設コストへ移行する。

- 大型ロッカー: 現在のレシピと同一コスト
- 壁掛け作業台: 現在のレシピと同一コスト
- スキャン室: 現在の建設コストと同一
- その他既存モジュール: 現在の建設コストを変更しない

新規設備のコストは以下を使用する。

- 梯子: 鉄インゴット12
- 開放型出入口: 鉄インゴット16、ガラス8
- 充電ステーション: 鉄インゴット16、銅インゴット16、ガラス8
- 水槽: 鉄インゴット24、ガラス32、銅インゴット8
- 深海生物捕獲容器: 鉄インゴット4、ガラス4
- 海流発電機: 鉄インゴット48、銅インゴット32、ガラス16
- 地熱発電機: 鉄インゴット48、銅インゴット24、ガラス8
- バイオ燃料発電機: 鉄インゴット32、銅インゴット32、ガラス8

constraints:
- 新規素材・新規中間素材を追加しない。
- 既存の生体油はそのままバイオ燃料として使用する。
- 既存の habitat 殻・ガラス・鉄・銅などを利用する。
- 既存建設物のコストは不用意に変更しない。

### 削除するクラフトレシピ

建設装置へ移行するため、以下の「完成設備そのもの」のクラフトレシピを削除する。

- 大型ロッカー
- 壁掛け作業台
- 海流発電機
- 地熱発電機
- バイオ燃料発電機
- 充電ステーション
- 水槽
- 梯子
- 開放型出入口

ただし以下はクラフト可能なまま維持する。

- 深海生物捕獲容器
- 生体油
- 既存の建設材料
- 建設設備の素材となる通常アイテム

捕獲容器については「専用アイテム」であるため、建設物ではなく通常アイテムとして扱う。

accept:
- 全BT01機能が建設装置のカテゴリから到達できる。
- 大型ロッカーと壁掛け作業台を建設装置から設置できる。
- 3種の発電機を建設装置から設置できる。
- 梯子、水槽、充電ステーション等を建設装置から設置できる。
- 対象設備のクラフトレシピが存在しない。
- 捕獲容器など、設備ではないアイテムのレシピは維持される。
- Forge 1.20.1 / NeoForge 1.21.1 の双方でメニュー構成が一致する。

## ファイル非重複ルール

今回の分割では、各エージェントが同じファイルを編集しないようにする。

- BT01a = 建設装置の共通UI・配置基盤
- BT01b = 解体専用
- BT01c = 梯子・上下接続専用
- BT01d = 発電機3種専用
- BT01e = カスタマイズ・充電専用
- BT01f = レーダー強化専用
- BT01g = 水槽・捕獲・養殖専用
- BT01h = 最終メニュー登録・レシピ削除専用

特に重要なのは、**BT01b〜g は建設メニュー本体を直接編集しない**ことです。各機能は「建設項目として登録可能な実装」を作り、最後に BT01h が一括登録します。

これなら Claude を子仕様ごとに分けて投入しても、同じファイルを複数エージェントが奪い合う構成になりません。
