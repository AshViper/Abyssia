# AB02 調査結果（2026-10-09、NeoForge ツリー、読み取り調査）

略記: W = src/main/java/com/abyssia/worldgen、C = W/cave、GW = tools/gen_worldgen.py

## 洞窟システム
- **全部が海底相対・2D グリッド 1 枚**。全システムは「深海底のすぐ下」に置かれ、Y は `CaveNetwork.seabed(x,z)`（ルーターの `initial_density_without_jaggedness` を二分探索）から決まる。帯の概念はない。装飾・空洞・地質・植生はほぼ深度非依存で、配置と入口だけが依存する。
- パイプライン: `OceanChunkGenerator.applyCarvers`(431-440) → `CaveGenerator.generate`(C:45): systemsNear → CaveChunk.create → computeField → carve → CaveGeology.paint → placeFills/Ores/Cuts → MassiveCavernDecorator.water → ThermalCaveGenerator.vents → CaveDecorationGenerator → 植生 → …、最後に `TerrainCaveDecorator.decorate`（密度関数の洞窟用、全チャンク）。`aquifers_enabled=false`、全ての空洞は水。`CaveChunk.carve()`(386-418) だけが WATER（ガスドームは AIR）を書く。
- `CaveNetwork`: セル = `Config caves.system_spacing`(既定 176、96..512)、1 セル 1 システム。MINOR_CELL 72/MINOR_REACH 56、LUMINOUS_REGION 640 + 240 ワープ(:55,243)。Y: `minY = max(noise.minY, DEEP_BOTTOM_Y)`(:88)、`maxY = min(top, CEILING_BOTTOM_Y=-88)`(:89)、`maxEntranceY = maxY-8`(:171)。`seabed()`(:183)の二分探索は「固体→空洞が 1 回だけ」を前提（AB02 で最深層を固体にしたので minY を -1862 まで下げても単調）。`biome()/profile()` は固定 `BIOME_QUART_Y = -240` で生物群系を引く(:53,225)。キャッシュ: plans 16384 / systems・minors 4096、超えたら全消去(:292,330)。`systemsNear`(:359)は 2*cellSize(352) 以内のセルを走査。
- `CaveNetworkGenerator`: `plan()`(:56-129) が軽い Plan(type, radius, hub xyz, env, waterLevel, grand)、`build()`(:133) が type で分岐。`y = lowestSeabed - cover - ry`(:84-99)、seabed ゲート(:65)。分岐 SIDE/DEEP/SHAFT/THERMAL(:338)。コネクタ(:580)は東と南の隣セルのハブへ、確率 = 両者の connection_chance の平均 × Config。`entranceTo`(:193) は 12 地点を試し、失敗なら天窓シャフト(:438)、それも駄目なら入口なし（システムは生成されるが閉じる）。`mayReach`(:556) 先読み。`buildMinor`(:599) の小洞窟/アーチ/侵食通路は海底に固定。
- `CaveType`(C:14-26): SMALL 3-8, MEDIUM 8-16, LARGE 16-32, MASSIVE 32-64, UNDERGROUND_SEA 40-72, TRENCH 10-24(高さ), VERTICAL_SHAFT 4-10, SEA_TUNNEL, SEA_ARCH, ERODED, MINERAL/CRYSTAL/THERMAL。サイズ → Rarity(COMMON/UNCOMMON/RARE)。`CaveLandmark` 7 種 r30-68。
- 現状の最大: MASSIVE_CAVERN r32-64、UNDERGROUND_SEA r40-72、ランドマーク r30-68（sizeBias 0.85-1.15）。ローブのオフセット 0.35-0.7r なので片側約 1.5r（幅 130-200）、高さ ry=r*vertical(0.3-0.85) で最大約 55。**128-256 幅の空洞は未存在**。
- `Cavern/CavernPlanner/CavernFormations/MassiveCavernDecorator`: r>=16 で Tier SMALL(<24)/LARGE(<40)/MASSIVE(>=40)(CavernPlanner:51)。テンプレ選択(:83)、パッチ、構造物数 = 密度 × 面積を階層ごとに上限(CavernStructure:15-31: massive は pillars 10, wall_caves 40, lakes 2)。配置時に全部 shapes 化し、MassiveCavernDecorator がチャンクごとに装飾（海底は使わない）。
- 選択: プロファイル = アンカーの生物群系(Y -240 固定) → `CaveProfile`(cave_types の重み、Config の LARGE/MASSIVE 係数)。環境: landmark > type.environment > profile.environment、「luminous」入れ替えは 640 セル領域の乱数(:123-125)。副洞窟は `net.environmentId("mineral"/"crystal"/"luminous"/"thermal"/"underground_sea")` を名前で引く。
- データ(GW): `CAVE_ENVIRONMENTS`(:995) abyssal, luminous, thermal, crystal, mineral, eroded, forest, underground_sea, trench（**toxic/frozen/anomalous は無い**）。`CAVE_PROFILES`(:1153) の項目: biomes, system_chance, minor_cave_chance, connection_chance, cave_types{type:weight}, minor_types, landmark_chance, landmarks, environment, luminous_chance, strata[(depth,block)], ores{block:weight}, cavern_templates{id:weight}, crystal_colors。8 プロファイル。system_chance 0.7-0.8、small 20-30/medium 15-28/large 6-14/massive 2-3、landmark 0.02-0.035。**abyss_* 生物群系にはプロファイルが無い**（GW の assert は DEEP_BIOMES だけ）。`CAVERN_TEMPLATES`(:1244): forest, crystal, mineral, thermal, lake, ruins_like_geology, mixed。`CRYSTAL_COLORS`: cyan, blue, violet, green, white, amber。
- 地質: `CaveGeology` は壁 3 ブロックを塗る。`profile.strata` は海底からの深さ(0..512)。`OceanChunkGenerator.deepStoneToRock`(397-428) は Y<-140 の石を全て abyssal_rock にする（帯別の岩はここ）。
- ペナルティ/リスク: ① `CaveChunk` のバッファは全 shapes の Y 範囲の合併 × 324 セル × 約 21 バイト（:89-119）→ 複数帯の shape が同じチャンクにあると約 1700 ブロック分のスパン（約 11MB/スレッド）。**帯ごとにパイプラインを 1 回ずつ回し、窓で絞る**こと。② キャッシュ上限が帯ごとに割れて再構築を繰り返す。`Site.floor()/ceiling()` は最大 200 ブロック走査、PlantEntry の高さ ≤200、Forest ≤120。③ 巨大空洞(r128+)は systemsNear の 352 保証と階層上限(massive: pillars 10 ...)を超える。④ `SeabedStructures` の空洞アンカーは XZ のみ。⑤ 流体は WATER/AIR のみ（溶岩・毒液は未対応、`setBlockState(..., false)` で流体ティックなし）。光源は発光植物だけ。⑥ 乱数ストリームには帯を含めること（cellSeed/Plan のソルト）。コネクタは同じ帯の隣だけ。

## 鉱石
- 24 金属は全て鉱石ブロック + raw/ingot が存在（`gen_deep_assets.py:154-181`、MINERALS）。MK0: 鉄(abyssal_iron_ore)、銅(deep_copper_ore)、金/レッドストーン/ラピス/ダイヤ/エメラルド(abyssal_<m>_ore)。**石炭は無い**。`ExcavatorMinerals.MIN_TIER`(J/industry:22) は既にオーナー定義と一致（Mk1 が MK0+MK1、Mk2 が 8 種の MK2）。
- **全ての鉱石は深海層の海底(Y -100..-362)だけに生成**。最深層・岩の中・洞窟には無い（洞窟は装飾的な「mega ore」だけ）。深さの条件は全部 A 帯(Y -94..-279)にある。
- 生成: GW:660-759。`MINERALS`(660)、`MINERAL_MIN_DEPTH`(674)、`RARE_MIN_DEPTH`(675)、`VEIN_PLACEMENT`(677: small count 2/chunk、medium 1/2、large 1/5、huge 1/14)、`VEINS`(678)、`RARE_VEINS`(699)、`VANILLA_VEINS`(723)、`vein_floor`(737)、`veins()`(745)。装飾ステップ 6。Feature = `abyssia:ore_vein`(`OreVeinFeature`)。鉱脈サイズ Config: small 5-15, medium 15-40, large 40-100 (× LARGE_VEIN_MULTIPLIER), huge 100-300。
- 現在の最小深度(m → Y): iron/copper/vanilla は無制限; manganese 2500m(-127), nickel 3500(-160), cobalt 4500(-202), titanium 2500(-127, 1/14), lead 1500(-94, 1/12), zinc 0(1/12), molybdenum 3500(1/18), vanadium 3500(1/18), neodymium 4000(-177, 1/48), uranium 4500(1/56), yttrium 4500(1/56), thorium 4500(1/56), platinum 5300(-242, 1/48), tellurium 5300(1/40), iridium 5300(1/64), tungsten 6100(-279, 1/48)。max_depth は使われていない。
- **鉱石は「採掘機でのみ」**: 金属はハンド採掘不可(`DEPOSIT_ONLY` gen_deep_assets:191)。`OreVeinFeature.place` が `ExcavatorMinerals.RAW_ITEM` にある鉱石で `OreDepositManager.enqueue` → `OreDepositData`(SavedData)に有限鉱床を登録、採掘機(Mk1 半径32 / Mk2 48)が一番近い鉱床を掘る。鉱床の登録は OreVeinFeature 経由でないと起きない。
- `OreVeinFeature`: ノイズで歪めた 1 つの体。露出（海底をまたぐ。EXPOSED_VEIN_CHANCE、large ×2、huge ×3）か、海底の数ブロック下に埋没(cy = floor - r - 2 - rand(6))。到達 ±13 ブロック。置換対象は tag `abyssia:vein_replaceable`（40 種の岩/堆積物/洞窟岩）。**床の探索が `DeepFloorPlacement`（Y -64 から下へ走査して最初の固体）直結**なので、最深層の岩の中には置けない → 「地殻モード」(floor を使わず指定 Y に置く)が要る。
- 深さフィルター `abyssia:depth`(DepthFilter) = その位置の Y のメートル換算。`DepthZone` 表 BLOCKS {0,40,100,200,300,380,392,2000} → METRES {0,200,1000,4000,6000,11000,11750,17000}。メートル(帯): Y-64=827m, -100=1690, -300=7438, -362=11312, -368=11688, -376=11773, -650=12667, -1100=14137, -1550=15606, -1865=16634。地殻内は約 3.3 m/ブロックなので帯の鉱石ゲートは **メートルでなく Y（height_range）で書く**。
- 設定: Config は 1 つの COMMON スペック(`Config.java:526`)、root は push("deep_ocean")。ore 節(37-59)、caves 節(101-134)。Config が生成 JSON に届くのは `ConfigPlacement`（`abyssia:config` 配置修飾、固定オプション vegetation/giant_plants/glowing_plants/abyssal_forests/crystals/thermal_vents → 個数の倍率）だけ。新オプションを足せば帯/ティア別の倍率が作れる。データレジストリ: `abyssia:cave_profile / cave_environment / cavern_template / seabed_structure / seabed_structure_profile`（GW が生成）。
- 洞窟の鉱石: `CaveProfile.ores`(重み付きブロック) → `oreBodies`(CaveChamberGenerator:396) と `CavernFormations.megaOres`(:522)。深さ条件なし、MK2 なし。採掘機鉱床には登録されない。
- MK1/MK2 を使うレシピ: 精錬→粉→合金(abyssal/corrosion/high_strength/heat_resistant/conductive/thermal/tungsten alloy)、工具・潜水装備・圧力装備、機械部品、潜水艦深度船体 Mk2(titanium)/Mk3(tungsten)。未使用に近い: lead(エネルギーセルのみ)、zinc(corrosion のみ)、thorium(thermal_alloy のみ)、uranium(advanced_energy_cell のみ)、iridium(tungsten_tip のみ)。

## 既存の環境危険
- 圧力(プレイヤー): `PressureGear`。ティア = 4 防具スロットの最小。安全メートル {0:200, 1:1700, 2:6000, 3:無制限}（ハードコード、Config は PRESSURE_ENABLED のみ）。超えると 1〜3 ダメージ/秒 + 鈍足、潜水艦内は除外。**ティア 3 は無制限なので最深層(16.6km)にもプレイヤーの圧力危険は無い**。ティア 2 の安全 6000m = Y -277。
- 圧力(潜水艦): `Submarine.crush`(587-598): 船体 4 + (深さ-定格)/200 ダメージ/秒、40(圧力船体 70)で破壊。定格 300/600/1000/2000m（Mk3 でも Y -110 まで）。
- 呼吸: `DivingBreathing`（装備ステージ 0/1/2、耐久消費）、居住区の淀んだ空気(`HabitatLifeSupport`)。
- 熱: `thermal/`（ThermalVentType, VentActivity, ThermalTemperature 0..1）はパーティクル/霧/鉱物帯にのみ使用。直接の熱ダメージは `MoltenRockBlock.stepOn` のみ。対策はモリブデンのツルハシ(heat_guard, IS_FIRE 半減)。**熱負荷・耐熱防具は無い**。
- 寒さ: MobEffect `cold_shock`（-15% 速度/レベル）が HelmetJelly の攻撃で付くだけ。frost_abyss は見た目のみ。
- 他の効果: deep_sight, abyssal_current, pressure_fatigue, murk。
- **存在しない**: 毒ガス/ガス危険（洞窟のガスポケットは無害）、環境熱負荷と耐熱装備、環境凍結と断熱装備、放射線、酸/腐食。
