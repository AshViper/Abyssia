## 座標系 (JSON 共通)
- 単位 px (16px = 1 ブロック)。原点 = ドックセル (ムーンプール y3) の底面中心。x 右、y 上 (下は負)、z 後ろ (艇のノーズは -z)。
- ドックセル x,z = ±8, y 0..+16。天井下面 = +16。床上面 = -32。水穴の縁 |x| または |z| = 56。水面 ≈ -33.6。
- 艇 (ドック時): x ±26, y -40.8..-4.8, z ±35.5。
- 回転は Z 軸のみ。単位は度、グループの pivot 周り、**正 = x→y 反時計回り**。右アーム (+x) は負で下がり、左アーム (-x) は正で下がる。子グループは親の回転を継承。全キューブの座標は **IDLE 姿勢** (= 基本姿勢)。IDLE の回転は arm 系 0、gangway_bridge のみ -80 (v2、下記)。

## 見た目
- 天井に頑丈な梁 (ダーク金属 + 天井側にメタル板、z ±19) とベース (x,z ±8 の筒状本体、底面中央にティール発光窓)。
- 梁の z = ±14 の 2 レーンから、左右 2 本ずつ計 4 本の 2 関節アーム (上リンク + 下リンク)。肩/肘はダーク金属ジョイント、上リンクにシリンダー (ダーク本体 + メタルロッド) を飾りで追加、ハザード縞は肘付近と先端付近だけ (オレンジの面積を抑える)、下面と内側パッドにティール発光ストリップ。
- 下リンク先端はパッド 2 枚 (上下) + 中央メタルブロックで船体側面を「挟む」形 (船体との隙間 1.3px、実際には挟まない)。
- 右舷 (+x) の床縁 (x=58, y=-32) にヒンジ式の階段状ガングウェイ。5 段 (踏面 5px x 段差 4px、グレーチング) + 着地台 (上面 y=-4、船体上面 -4.8)。各段の下にダーク支柱、両側に手すり (z ±6..8、段ごとに折れる)。着地台にティール表示灯。ヒンジ根元に固定マウント (ハザード縞付き)。
- ベース/アーム/ガングウェイとも船体 (±26) には触れない。

## 状態とアニメ (数値は JSON の animation / timing_ticks と一致)
| 状態 | 上リンク | 下リンク | ガングウェイ |
|---|---|---|---|
| IDLE | 0° | 0° | -80° (ほぼ垂直に跳ね上げ) |
| CAPTURE 終了 | 右 -20° / 左 +20° | 右 -70° / 左 +70° | -60° |
| DOCKED | 同上 | 同上 | 0° (展開) |
| RELEASE 終了 | 0° | 0° | -60° |

IDLE: 4 本のアームは天井沿いに左右へ水平に伸ばした状態 (先端 x=±74、y 3..13)。中央の視界を塞がない。
- CAPTURE (30 tick): 艇の引き上げと同時に開始。上リンク 0..18 tick、下リンク 6..24 tick (ease_in_out_cubic)。24..30 は保持 (固定音/ティール発光点灯)。艇の上昇中も常にパッドの x が 27.3 以上 (> 26) のため艇に衝突しない。
- DOCKED: CAPTURE 完了後 6 tick 置いてからガングウェイを 14 tick で展開 (ease_out_cubic、最後に軽い「カチッ」の SE)。以降、アーム保持・充電/修理は現行どおり。
- RELEASE (34 tick): ガングウェイ収納 0..14 tick (ease_in_cubic) → アームを開く: 下リンク 14..28、上リンク 20..34 (ease_in_out_cubic)。ガングウェイを先に退避してからクランプ解除。
- ティール発光: IDLE 消灯 / CAPTURE 点滅 / DOCKED 常時点灯 / RELEASE 消灯 (レビュー提案。実装は任意、dock_light を emissive/最大明るさで描く)。

## 検証結果 (Claude が数値で確認、2D ポリゴン SAT、各遷移 40 ステップ補間)
- アーム/ガングウェイと艇ボックスの最小隙間: **1.31px** (下リンク内パッド x=27.3 vs 艇 26)。遷移 IDLE->CAPTURE->DOCKED->RELEASE->IDLE の全区間で艇ボックスに侵入なし。
- 上リンクと艇上角: 約 6px、DOCKED で肘位置 (±34.3, 0.4)、パッド下端 y=-37.6 (艇底 -40.8)。
- 天井: 全姿勢で最大 y=16.00 (天井下面ちょうど、突き抜けなし)。
- 範囲: IDLE x -74..76.7 / y -33..16 / z ±19、DOCKED x -37.3..66 / y -37.6..16。ベースの z 梁 ±19 はドックセル (±8) より広い (天井下面に沿った空気セルの範囲。レンダーバウンディングボックス拡張が必要)。
- DOCKED でガングウェイと腕の最小間隔 25.7px (xy)、収納 (-60°) ガングウェイは x 最大 76.7 / y 最大 12 で部屋内 (内壁 ±88 想定) に収まる。着地台 x=28 (艇側面 26 との隙間 2px)。
- ベースと肩ジョイントの重なりは意図したヒンジ (4 か所)。

## 実装メモ
- ガングウェイの当たり判定 (プレイヤーが歩く面) はモデルと別に必要。踏面: 5 段 x[53-5k..58-5k] 上面 y=-28,-24,-20,-16,-12 (k=0..4)、着地台 x 28..33 上面 y=-4 (-5 の板 + 表示灯 1px)。一段 4px (< 9.6px のステップ高)、着地台へは 8px 上がり (許容)。
- ガングウェイの根元 (x=58, 床上面 y=-32) は水穴の縁 (x=56) の外側。降りるプレイヤーはここに立つ現行挙動に合う。
- 収納 (IDLE) は x 58..77 に壁状に立つ。デザイン上、跳ね橋の見せ方。
- 最上位のコンセプト画像は構成確認用 (アームが船体の外から回り込むシルエット)。実モデルは JSON が正。

## ChatGPT レビュー (要約と反映)
- 総評: 2 レーン化 / 跳ね橋化 / IDLE 格納 / RELEASE の順序 (ガングウェイ→下リンク→上リンク) は合格。
- 反映済み: (1) パッド上下 2 点 + 中央ブロック化、(2) 上リンクに飾りシリンダー、(3) ハザード縞を肘付近と先端付近に限定、(4) ティール発光を線に限定、(5) 着地台に表示灯、(6) ease をふわっとした sine から cubic に。
- 見送り: ガングウェイ先端の可動ラッチ (アニメ追加は任意、将来案)、ウインチ (吊り上げ荷重表現が紛らわしいため)。

- 注意: 発光/アニメは見た目のみ。ゲーム動作 (捕捉/保持/充電/Ctrl 解放/降車位置) は変更しない。

## v2 ガングウェイ改訂 (2026-10-04, 歩けない問題の修正)
部屋は高さ 3 ブロック (床上面 -32 .. 天井 +16 px) で、プレイヤー (0.6 x 1.8 = 28.8 px) の足は -12.8 px 以下でないと頭が天井に当たる。v1 の階段 (最上段 -12 / 着地台 -4) は歩けなかった (歩行テストで確認)。
- v2: 低い平らな橋。デッキ上面 y=-24 (床 -32 から 8 px の段差 1 つ)、x 28..58、z ±8、厚み 3 (+ 下に桁)。ヒンジ = デッキ上面の縁 (58, -24) (ヒンジ位置を上面にしたので跳ね上げてもマウント (x>=58) に食い込まない)。
- 固定マウント: x 58..66, z ±10, 上面 -24 (ハザード)。床 -> マウント -> デッキと 8 px の段差で上がる。
- 手すり: 両側 z ±6..8、上端 -15。IDLE は -80° でプール縁にほぼ垂直に立つ (x 47..58, y 最大約 6)。
- 検証 (数値): プレイヤー足 -24 -> 頭 4.8、天井まで 11.2 px (0.7 ブロック)。アーム/パッド/梁のキューブは全て |z| >= 9、デッキ・手すりは |z| <= 8 (プレイヤー 4.8) -> どの姿勢でも干渉せず、アームとの横間隔 >= 4.2 px (0.26 ブロック)。回転は Z 軸のみなので z 間隔は遷移中も不変。デッキは x >= 28 (船体 26)、水面 -33.6 より上 (桁の最下 -32)。
- 当たり判定 (ヘルパーブロック、床層 y1 のみ): デッキ上面 -24 (厚み 8 px の柱)、x 24..72 の 3 セル、マウントも含む。降車位置 = デッキ上 x=34 px。
