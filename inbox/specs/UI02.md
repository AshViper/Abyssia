# UI02 Vanilla container screens in the deep-sea theme

Follows UI01 (`inbox/specs/UI01.md`, palette and `tools/ui_kit.py`). Base NeoForge 1.21.1, then Forge 1.20.1.
Scope (user, 2026-10-10): every vanilla container screen — player inventory (survival, creative), chest, large chest, barrel, ender chest, shulker box, hopper, dispenser/dropper, furnace, blast furnace, smoker, crafting table, recipe book, anvil, enchanting table, brewing stand, beacon, villager trading, horse, stonecutter, loom, cartography table, grindstone, smithing table, crafter (1.21 only).

## A. Textures — `tools/container_ui.py --loader neoforge|forge --root <tree>`
- Reads the vanilla PNGs from the local client jar at generation time (1.21.1 `C:\Users\nagis\.gradle\caches\neoformruntime\artifacts\minecraft_1.21.1_client.jar`, 1.20.1 `C:\Users\nagis\.gradle\caches\forge_gradle\minecraft_repo\versions\1.20.1\client.jar`); fails loudly if missing.
- Recolour, writing to `<root>/src/main/resources/assets/minecraft/textures/...`:
  - exact vanilla GUI greys by role: `000000` outline → ABYSS, `373737` slot shadow → ABYSS, `555555` panel shadow → NAVY_DEEP, `8B8B8B` slot fill → NAVY_DEEP, `C6C6C6` panel → NAVY, `FFFFFF` highlight → STEEL (slot bottom-right) / STEEL_LIGHT (panel bevel) — tune by eye;
  - other low-saturation pixels through a monotonic ramp anchored on those roles;
  - saturated pixels (flame, bubbles, XP, red/green marks, lapis) unchanged;
  - alpha unchanged.
- Files: 1.21.1 `textures/gui/container/**`, `textures/gui/sprites/container/**`, `textures/gui/recipe_book.png`, `textures/gui/sprites/recipe_book/**`, `textures/item/empty_*` slot icons. 1.20.1: the same folders' sheets (`container/*.png`, `container/creative_inventory/*`, `recipe_book.png`, `item/empty_*`).
- For every overridden PNG, also write the vanilla `.png.mcmeta` if the jar has one (metadata is read from the pack that supplies the PNG).
- Excluded: enchanting-table clue button art (1.21.1 `sprites/container/enchanting_table/enchantment_slot*`; the matching button region of the 1.20.1 sheet), because the clue text is drawn in brown 0x685E4A on it. Also excluded: non-container files (stats icons, gamemode switcher, bundle).
- No ornaments in v1.
- Outputs are Mojang derivatives (precedent: vault decision vanilla-recolour-textures). List them in the vault and remind the user before a public release.

## B. Label readability — `com.abyssia.client.gui.VanillaContainerLabels` (client, both loaders)
- Vanilla `renderLabels` draws titles in 0x404040, which is unreadable on navy.
- Handler on `ContainerScreenEvent.Render.Foreground`: it fires after renderLabels with the pose translated to leftPos/topPos. It runs only for screens whose class is in `net.minecraft.`. It redraws the same strings at the same coordinates with `drawString(font, text, x, y, UiTheme.TEXT, false)`.
- Label positions are read from `AbstractContainerScreen.titleLabelX/Y, inventoryLabelX/Y`, without an AT (Forge has none):
  - NeoForge: plain reflection with official names.
  - Forge 1.20.1: `ObfuscationReflectionHelper.findField` with SRG names (confirm from the 1.20.1 mappings in the gradle cache).
  - Cache the Fields.
- Per-class cases, copied from each version's renderLabels:
  - InventoryScreen: title only.
  - CreativeModeInventoryScreen: selected tab name at (8,6), only when that tab shows its title.
  - MerchantScreen: centred title, the "Trades" label, and the level/XP text.
  - BeaconScreen: skip (already light).
  - All other default screens: title and player inventory title.
