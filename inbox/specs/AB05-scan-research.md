# AB05 スキャン解放（研究）システム（プラン: ChatGPT、2026-10-09。レビュー・契約: Claude）

依頼: Subnautica のように、対象をスキャンしてデータベースに登録し、設計図（レシピ・機械・建築メニュー・装備）を解放する。ChatGPT 会話「Abyssia解放システム設計」の要点:

## ChatGPT のプラン（要点）
- 基本ループ: 探索・スキャン → データベース登録 → 設計図（技術）解放 → 深部へ。**記録（図鑑）と使用権（技術）は別データ**。既存の WreckProgress は新システムへ統合、HabitatBuilder のチェックは技術解放 API を呼ぶ形にする。
- 解放単位 = 「技術」(ResourceLocation, 例 `abyssia:technology/...`)。技術が解放キー（`recipe_group/…`, `machine/…`, `building/…`, `equipment/…`, `upgrade/…`）の配列を `unlocks` に持つ。技術定義 JSON: id, type, title, tier(mk0..2), depth_band(A..E), `scan_requirements`[{target, count}], `prerequisites`[], `unlocks`[], icon。未定義 ID・循環依存・重複は読込時エラー。リロードでプレイヤーの解放済みは消さない。
- 739 レシピへの割り当て: レシピ ID → 技術キーの対応表 `recipe_unlocks.json` を**生成ツールが別途出力**（バニラのレシピ JSON は変えない）。機械の実行時レシピ、合金炉6・分離機3の固定表、建築メニュー約25エントリにも同じキーを付ける。
- スキャン対象の分類: 生物38、資源植物58、鉱物24、残骸・断片、熱水噴出孔、海底構造物69、環境(洞窟13・広間)、技術設備。最初は残骸・鉱床・熱水噴出孔の3系統で縦切り。同じ対象の図鑑登録は 1 回、技術進行への寄与もプレイヤーごとに初回のみ。断片は発見キー（位置+種類）で重複加算を防ぐ。
- 操作: 右クリック長押し。生物・鉱床 4〜6 秒、残骸断片 6 秒、大型構造物 8〜12 秒。基本距離 16（MK0）/24（MK1）/32（MK2、時間短縮 20%/35%）。サーバーが対象判定・進捗・完了検証を管理（連続レイキャスト、視線逸脱 0.2〜0.3 秒の猶予、中断条件）、クライアントは描画だけ。既存の 128 ブロック検知は「候補探索」として残し、詳細スキャンは近距離。HUD: 対象名・距離・進捗、未解析/解析済み/断片 n/m、完了音・通知。
- ゲーティング: 推奨は「レシピロック + 利用時のサーバー検証」。機械（粉砕機・精錬炉・合金炉・分離機）はレシピ選択・開始・完了時、建築メニューは表示と要求受信時（HabitatBuilder.startBuild）、装備作成・スキャナー強化も検証。バニラの作業台・かまどにプレイヤー別の口は無いので、MVP では Mixin を使わず独自機械・建築・専用画面から対応。JEI は既定で未解放を隠す（設定可）。ガイドブックは「？」表示+ヒント。
- 保存・同期: PERSISTED NBT に schema_version, scanned_targets, fragment_counts, unlocked_technologies, database_entries。ログイン時全件同期、完了/解放時は差分、リスポーン引き継ぎ（PlayerEvent.Clone）。クライアントから来たキーをそのまま保存しない。既存ワールド: WreckProgress の残骸数を移行（3 個以上は居住区コンストラクタ解放）、所持品からの救済は許可リスト。creative/OP 免除は設定。コマンド `/abyssia research check|unlock|reset <player> [tech]`。
- 図鑑 UI(最小): カテゴリ切替（生物/資源/技術/地点）、状態表示（未発見/解析済み/断片不足）、説明・深度帯・条件・関連技術、技術タブで設計図と進行条件。表示専用。壊れた ID でもクラッシュしない。
- 実装順: (1) 基盤: TechnologyManager・JSON 読込・NBT 保存・同期 Payload・コマンド (2) 縦切り: LidarScannerItem 拡張で熱水噴出孔か残骸コアをスキャン→図鑑登録→技術解放→居住区建築、再ログインで維持 (3) 機械・建築のロック (4) レシピ生成ツール・JEI・図鑑 UI (5) A〜E・MK0〜MK2 への展開、旧ワールド移行、Forge 移植。

## 契約（担当 R = 基盤、S = スキャン操作・HUD・図鑑UI。名前を変えない）
パッケージ `com.abyssia.research`。
- **R（基盤、サーバー側 + 同期）**: `ResearchManager`（静的 API）: `boolean isUnlocked(Player, ResourceLocation tech)`、`boolean isTargetScanned(Player, ResourceLocation target)`、`ScanOutcome scan(ServerPlayer, ResourceLocation target, String discoveryKey)`（`ScanOutcome` = enum {NEW, FRAGMENT, KNOWN} と新規解放した技術 ID のリストを返す record `ScanResult(ScanOutcome outcome, int fragments, int needed, List<ResourceLocation> unlocked)`。完了時に差分同期 + 解放トースト用 payload を送る）、`void unlock(ServerPlayer, ResourceLocation)`、`void reset(ServerPlayer, @Nullable ResourceLocation)`、`boolean bypass(Player)`（creative、config `research.op_bypass`）、`boolean isBuildingUnlocked(Player, String buildingId)`（技術の unlocks に `abyssia:building/<id>` があるか）。`ResearchData`（PERSISTED NBT、schema_version）、`TechnologyRegistry`（`data/abyssia/technologies/*.json` を ReloadListener で読む。検証: 未定義・循環・重複）、`ScanTargetRegistry`（`data/abyssia/scan_targets/*.json`: id, category, name_key, scan_seconds, range, `match`: {"block": id | "block_tag": id | "entity": id | "deposit_mineral": id | "structure": id}, `fragment_key`: "position"|"type"; メソッド `Optional<ScanTarget> find(ServerPlayer, HitResult)` と `String discoveryKey(ScanTarget, HitResult)`）、クライアント側 `ClientResearch`（同期された状態: `isUnlocked(id)`, `isScanned(id)`, `fragments(techId)`, `technologies()`, `targets()`）、Payload（全件同期 `ResearchSyncPayload`, 差分 `ResearchDeltaPayload`, 解放通知 `TechUnlockedPayload`）、コマンド `/abyssia research check|unlock|reset`、既存 WreckProgress の移行（ログイン時: 旧 `abyssia_wrecks` の件数から wreck 対象のスキャン済み・断片を復元）、HabitatBuilder.startBuild のゲートを `isBuildingUnlocked(player, "habitat_constructor")` に置換（creative 免除は維持）、Config 節 `research`。初期データ（NeoForge の data）: 対象 `scan_target/wreck_core`(fragment_key position)、`scan_target/thermal_vent`、`scan_target/mineral_deposit_manganese`、`scan_target/mineral_deposit_cobalt`、技術 `technology/wreck_research`（wreck_core 3 個 → unlocks `abyssia:building/habitat_constructor`）、`technology/thermal_survey`（thermal_vent 1 → unlocks `abyssia:building/geothermal_generator` は実在する建築 ID に合わせる）、`technology/basic_metallurgy`（鉱床 1 → `abyssia:machine/alloy_furnace`）など 6〜8 個。
- **S（スキャン操作・HUD・図鑑 UI）**: `LidarScannerItem` の拡張: 長押し中、サーバーが毎 tick 視線の対象を `ScanTargetRegistry.find` で判定し、`PlayerScanState`（プレイヤーごと、メモリのみ: 対象 ID、開始 tick、猶予）で進捗を管理（視線逸脱 6 tick の猶予、距離超過・アイテム変更・死亡で中断、スキャナー段階の距離: 既存アイテムは MK0 = 16 ブロック、128 ブロックの鉱床一覧は従来どおり残す）、完了時に `ResearchManager.scan(...)` を呼び結果を通知（音・パーティクル・チャットではなく payload で HUD）。Payload `ScanProgressPayload(targetId, progress, state)`（数 tick ごと + 完了/中断で即時）、クライアント HUD オーバーレイ（`ScanHud`: 対象名、距離、進捗バー、「未解析/解析済み/断片 n/m」、完了時のフラッシュと「新しい設計図を取得: …」トースト）、図鑑画面 `DatabaseScreen`（キーバインド、カテゴリタブ: 生物/資源/技術/地点、項目の状態、説明、技術タブで解放済み/未解放と条件、`ClientResearch` だけを読む表示専用）、lang キー（`tools/lang_parts/ab05_research.json`）。既存の WreckProgress 呼び出し（`reportWreck`）は新 API に置換。
- **共有ファイル**: `network/AbyssiaNetwork.java`（R と S の両方が payload 登録を追加。Edit で自分の行だけを追加、編集前に再読込、PROTOCOL は R だけが上げる）、`Config.java`（R のみ）、`Abyssia.java`（R のみ）、lang は直接編集せず lang_parts。

## 第 2 反復（2026-10-09、ユーザー承認: 「次の段階に進めてよい」）
範囲: ゲーティングの実装 + コンテンツ拡張。**バニラの作業台・かまどでのクラフトの強制はしない**（呼び出し口が無い。Mixin 不使用の方針）。代わりに: 機械（置く・開く）と建築メニューの項目をロックし、クラフト品は JEI で未解放を隠す（表示のみ）。
解放キーの規則（データ駆動）:
- `abyssia:machine/<ブロックID の path>`: どの技術の `unlocks` にも現れないブロックは自由、**どれかの技術の unlocks に現れるブロックは、その技術が解放されるまでロック**（置く: `BlockEvent.EntityPlaceEvent` を取り消し、開く/使う: `PlayerInteractEvent.RightClickBlock` を取り消し、どちらも「未解放: <技術名>」のメッセージ）。creative と `bypass` は免除。
- `abyssia:building/<建築エントリ ID>`: 同じ規則で居住区建築メニューの項目をロック（サーバー: `HabitatBuilder.startBuild` がエントリ ID を検証、クライアント: メニューで鍵アイコン/灰色表示）。
- `abyssia:recipe/<アイテム path>`: そのアイテムを結果に持つレシピ（クラフト・精錬・機械）が、その技術で解放される（JEI は未解放を隠す。設定 `research.jei_hide_locked` 既定 true。強制はしない）。
- `abyssia:upgrade/scanner_mk1|mk2`: スキャナーの距離 16 → 24 → 32 ブロック、スキャン時間 x0.8 / x0.65（アイテムの追加はせず、技術の解放で段階が上がる）。
担当 A1（ゲーティング）: 上記の machine / building / recipe(JEI) の強制、ClientResearch の問い合わせ（`isBlockLocked`, `isBuildingLocked`, `lockedBy`）、設定。担当 A2（コンテンツ）: 技術約 30 件（深度帯 A〜E、MK0〜MK2、ChatGPT の設計表に沿う）、スキャン対象 50 件前後（鉱物 24 種・生物の代表種・資源植物の代表種・噴出孔・残骸・環境）、lang、スキャナー段階（PlayerScanState の距離・時間）、DatabaseScreen のカテゴリ対応。ファイル所有: A1 = research/ の新規 gate パッケージ、HabitatBuilder、habitat/client のメニュー、compat/jei、Config(research 節に追記)、ClientResearch に追加する問い合わせ。A2 = data の technologies/scan_targets、tools/lang_parts/ab05_content.json、PlayerScanState、DatabaseScreen。
