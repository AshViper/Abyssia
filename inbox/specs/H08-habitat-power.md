# H08 拠点ワイヤレス給電
tier: heavy
原本: inbox/specs/H08-chatgpt-raw.md (ChatGPT)。下記は Claude の修正込み確定版。ユーザー指定: 専用ポートなし、拠点の外側のどこからでも入力できる。
goal: 拠点の外壁 (どの殻ブロックでも) に外のケーブルを当てれば拠点に電気が入り、拠点内に置いた FE 機器 (工業機械・壁掛け作業台・スキャン台座・蓄電池) はケーブルなしで受電する。
constraints:
- 殻ブロック habitat_* に BlockEntity は足さない。判定・配電はサーバーのみ、保存データ (SavedData) で拠点構成と共有 FE を保持
- 拠点内のケーブル敷設も従来どおり使える (併用可)
accept: 外壁の任意の位置に接したケーブルから受電、拠点内の機器がケーブルなしで動く、繋がったモジュールは 1 つの拠点、繋がっていない拠点は電力が別、再起動後も共有 FE が残る

## 拠点の判定
- 建設装置がモジュールを完成させた時点で、モジュールの箱 (外寸) を保存データに登録 (ディメンションごと)。接続口が開通した / 壁が結合したモジュール同士は同じ拠点 (union)。繋がっていなければ別拠点
- 「拠点内」= どれかのモジュールの箱の中 (殻を含む)。「外壁」= 箱の外周の殻ブロック
- 修正: ChatGPT 案の「実装前の拠点を初回起動時に走査」は記録が無いので不可。H08 以前に建てたモジュールは対象外 (建て直し)。開発中のテストワールドのみなので影響なし
- 殻の解体機能は無いのでモジュール削除はしない

## 受電 (外壁から)
- 工業ケーブル網 (CableNetworkManager) が、ケーブルに隣接する habitat 殻ブロックを「受電先」として扱う: その殻が属する拠点の共有バッファへ入れる。ケーブル自体が拠点の箱の外にある場合だけ (箱の中のケーブルは通常の機器接続のみ)
- 修正: 1 本あたりの上限はケーブル自身の流量 (128 / 512 FE/t、ChatGPT の 20,000 は既存ケーブルを超えるので不採用)。拠点全体の受電上限 100,000 FE/t
- 他 Mod のケーブルは capability を探すので殻には繋がらない (仕様外。必要なら後で専用ブロック)

## 共有電力と配電
- 拠点ごとに共有バッファ 1,000,000 FE (損失なし)、保存データに保存
- 毎 tick (サーバー): 拠点内の FE 機器一覧 (BlockEntity の ENERGY capability) をラウンドロビンで配る。1 機器あたり最大 10,000 FE/t (機器の受電上限が低ければそちら)
- 機器一覧はキャッシュし、40 tick ごと + 拠点構成変更時に箱内のチャンクの BlockEntity を列挙して更新 (毎 tick のブロック走査はしない、ロード済みチャンクのみ)
- 拠点内の発電機 (extract 可・receive 不可): 毎 tick 共有バッファへ吸い上げ
- 拠点内の蓄電池 energy_device (両方向): 他の機器に配った残りで充電、共有バッファが空で機器が足りないときは蓄電池から共有バッファへ放電

## 表示
- 拠点の殻ブロックを素手でスニーク+右クリック → アクションバーに「拠点電力 650,000 / 1,000,000 FE ・入力 a FE/t ・出力 b FE/t」(修正: ChatGPT 案はデバッグ表示のみ。プレイヤーが見られる方法を追加)
- 各機器の既存 GUI の FE 表示・エネルギー不足表示はそのまま

## その他 (同時対応)
- 拠点の天井などで「水が垂れる」パーティクルが出る件: habitat_* と scan_console を `minecraft:impermeable` タグに追加 (ガラスと同じ扱いで滴下しない)
