# WR01 無線送電中継器

## tier

- Tier: 拠点設備 Tier 2
- 位置づけ: 拠点間・発電設備間の長距離 FE 送電を無線化する中継設備
- 電源生成機能は持たない。
- HabitatPower の共有 FE バッファを直接読み書きする設備ではなく、**WR01 同士の無線リンクを介して FE を輸送する**。
- 既存の工業ケーブルより長距離配電に向く代わりに、距離・リンク数・送電量に制約を設ける。

## goal

WR01 は、Abyssia の拠点設備として、

- 離れた拠点同士を無線で接続する
- 拠点から離れた発電設備へ工業ケーブルを長距離敷設せず接続する
- 離れた位置にある設備群へ FE を供給する

ための長距離送電設備とする。

特に、

`発電機 → WR01 → 無線 → WR01 → 拠点`

および

`拠点 A → WR01 → 無線 → WR01 → 拠点 B`

を主用途とする。

WR01 の導入によって、海底に大量の工業ケーブルを敷設する必要を減らす。

ただし、完全な無制限ワイヤレス電力網にはせず、

- 最大通信距離
- 最大リンク数
- 送電量
- 距離による損失

を設定し、工業ケーブルとの使い分けを成立させる。

## design

### 外観

WR01 は「深海基地用の無線送電塔」として設計する。

- 設置サイズ: 1x1 ブロック
- 高さ: 2ブロック
- 下部:
  - 暗灰色～濃紺の金属製筐体
  - 銅・鉄製の補強部品
- 上部:
  - 細いアンテナ柱
  - 最上部に円形または十字状の送受信用アンテナ
  - アンテナ中心に発光コア
- 全体として既存 Abyssia の拠点設備と同じ「工業設備 + 深海用発光」のデザインにする。

アンテナは周囲から見て WR01 であることが分かる程度に上方へ伸ばす。

### 配色

基本:

- 本体: 暗い青灰色 / 鉄灰色
- 補強: 暗銅色
- ボルト・細部: 鉄色
- 発光部: 青緑色（teal / cyan）

既存 Abyssia の深海設備で使用している発光色と統一する。

### 配置

WR01 は**屋外設置を基本**とする。

推奨配置:

- 拠点の外壁付近
- 海底
- 海底基地の屋上
- 発電機の近傍
- 離れた場所に設置した中継地点

拠点内部の床・壁にも設置自体は可能とするが、無線設備としての視認性を考慮し、基本的には屋外または外壁付近で使用する。

### 殻との関係

WR01 自体には「殻ブロックに接していなければならない」という設置条件を設けない。

ただし、拠点の `HabitatPower` に接続する場合は、

- 拠点の結合済みモジュール内に存在する
- または拠点外に設置され、工業ケーブル等によって拠点の FE ネットワークへ接続されている

ことを条件とする。

つまり、

`殻に接している = 自動的に電力接続`

とはしない。

これにより WR01 の設置判定と既存の拠点判定を分離する。

### リンク方式

**自動リンク方式**を採用する。

WR01 を設置すると、一定範囲内にあるリンク可能な WR01 を検索する。

ただし、近くにある全 WR01 と無制限に接続するのではなく、以下の条件でリンクを決定する。

- 最大リンク距離: 128ブロック
- 最大リンク数: 2
- 同じ WR01 同士の重複リンクは1本として扱う
- リンク可能な WR01 が複数ある場合、距離が近いものを優先
- 最大リンク数を超える候補はリンクしない
- リンク確立後は、候補が多少近くなっただけでは毎 tick 再選択しない

リンク情報は BlockEntity / サーバー側ネットワーク管理で保持する。

### 視線

**視線は不要**とする。

海底基地同士を接続する設備であるため、地形や基地を貫通できないと使い勝手が悪くなる。

したがって、

- 海水
- 石
- 土砂
- 基地の殻
- 建築物

によってリンクを遮断しない。

ただし、128ブロックという距離制限は厳守する。

### 発光線

リンクしている WR01 同士の間に、アンテナからアンテナへ伸びる発光線を表示する。

発光線は「物理ケーブル」ではなく、

**無線送電が成立していることを示す視覚的エフェクト**

として扱う。

仕様:

- 始点: アンテナ先端
- 終点: 相手 WR01 のアンテナ先端
- 色: 青緑～シアン
- 太さ: 約 1～2 pixel 相当
- 常時表示ではなく、低頻度のゆるやかな明滅
- 完全なレーザー状の一本線ではなく、わずかな揺らぎを持たせる
- 送電中は明るくなる
- リンク成立のみで送電していない場合は暗めにする

発光線は Minecraft の通常ブロックとして配置しない。

クライアント側 Renderer で描画する。

### アニメーション

リンク線には以下の状態を持たせる。

1. 接続中
   - 暗い青緑
   - 弱い明滅

2. 送電中
   - 青緑色が明るくなる
   - 線上を小さな光がゆっくり移動する
   - 送電方向に合わせて光が流れる

3. 送電量が大きい
   - 明るさを若干増加
   - 光粒子/流線の移動速度を若干増加

送電量を正確に読み取れる UI にはしない。
視覚的なフィードバックとして使用する。

### リンクなし

リンク先がない WR01 は、

- アンテナ先端を暗くする
- 発光コアを非常に弱く点灯
- 発光線を表示しない

状態とする。

完全に消灯させず、「稼働しているが接続先がない」ことが分かるようにする。

## mechanics

### FE 接続

WR01 は Forge の `ForgeCapabilities.ENERGY` を使用する。

既存の工業ケーブルと同じ FE システムに接続可能とする。

WR01 は、

- FE を受け取る
- 無線リンクへ送る
- 無線リンクから受け取る
- FE を外部へ出力する

の4方向を処理できる。

### エネルギーの流れ

基本的な流れ:

`発電機 → HabitatPower → WR01 → 無線リンク → WR01 → HabitatPower → 機器`

または、

`発電機 → 工業ケーブル → WR01 → 無線リンク → WR01 → 工業ケーブル → 機器`

を許可する。

拠点に接続された WR01 は、既存の `HabitatPower` を経由して拠点内へ配電できる。

これにより、

`発電機 → WR01 → WR01 → 拠点内設備`

のような長距離無線送電を実現する。

### 送電方向

リンクは**双方向**とする。

毎 tick、

- 送信側
- 受信側

を固定しない。

両端の FE 需要/供給状況を確認し、余剰エネルギーを持つ側から不足している側へ送電する。

例えば:

`拠点A: 800,000 FE`
`拠点B: 100,000 FE`

なら A → B。

逆に B 側の発電機が稼働して A が不足していれば B → A。

これにより同じ無線網を発電・送電の双方に利用できる。

### 無線送電量

WR01 1リンクあたり:

- 最大送電量: **512 FE/t**

既存工業ケーブルの 512 FE/t と同等とする。

ただし、距離による損失を設ける。

### 距離損失

128ブロックを最大距離とし、距離に応じて送電効率を変化させる。

| 距離 | 送電効率 |
|---:|---:|
| 0～32 | 100% |
| 33～64 | 90% |
| 65～96 | 80% |
| 97～128 | 70% |

例:

512 FE/t を送る場合:

- 32ブロック以下: 512 FE/t
- 64ブロック以下: 約461 FE/t
- 96ブロック以下: 約410 FE/t
- 128ブロック以下: 約358 FE/t

損失分の FE は消費される。

### バッファ

WR01 自体には大容量の独立 FE バッファを持たせない。

内部処理用としてのみ、

- 最大 1,024 FE

程度の一時バッファを持たせる。

これは送電処理の平滑化用であり、蓄電設備として利用できないようにする。

拠点側の主要な蓄電は既存の:

`HabitatPower = 1,000,000 FE`

を使用する。

### 複数リンク

WR01 は最大2本までリンク可能。

各リンクの上限は512 FE/t。

したがって理論上の最大中継送電能力は:

`512 × 2 = 1,024 FE/t`

とする。

ただし、1つの WR01 が 1,024 FE/t を常時受け渡す必要はない。

実際の送電量は、

- 入力可能 FE
- 出力要求
- HabitatPower の残量
- リンク先の需要
- リンクの損失

によって決定する。

### 中継

WR01 → WR01 → WR01 の多段中継を許可する。

ただし、1回の送電処理で無制限にネットワークを探索しない。

1リンク = 1送電区間として扱い、

`A → B → C`

の場合は A→B、B→C をそれぞれ独立した送電として処理する。

これにより複雑な無線ネットワークでも処理量を予測しやすくする。

### 自動再接続

リンク先が、

- 破壊された
- チャンクアンロードされた
- 128ブロック以上離れた
- WR01 ではなくなった

場合、そのリンクを無効化する。

リンク先が再び有効になった場合は自動的に再接続候補へ戻す。

ただし候補探索を毎 tick 行わない。

### 状態表示

WR01 を**スニーク右クリック**すると状態情報を表示する。

表示内容:

- 接続状態
- 接続先数
- 各接続先までの距離
- 現在の送電量
- 送電効率
- 送電方向
- リンク先の拠点名または座標
- 入力 / 出力状態

通常右クリックは既存の建設・設備操作体系と競合しないよう、必要に応じて GUI を開く。

スニーク右クリックは「状態確認」のショートカットとして固定する。

### 建設メニュー

カテゴリ:

**設備**

として登録する。

理由:

- 発電設備ではない
- 単なるモジュール構造ではない
- 拠点の電力ネットワークを拡張する設備である

BuildEntry:

- ID: `wireless_power_relay`
- 表示名: `無線送電中継器`
- カテゴリ: `設備`

### 建設コスト

既存の Tier 2 設備相当として設定する。

推奨:

- 鉄インゴット × 12
- 銅インゴット × 8
- レッドストーン × 8
- ガラス × 4
- 鉄ブロック × 2

合計:

- 鉄系: 14相当
- 銅: 8
- レッドストーン: 8
- ガラス: 4

既存の拠点設備より極端に安くせず、長距離ケーブルを不要にする利便性に対するコストを設定する。

BuildEntry の既存仕様をそのまま使用する。

- ホログラム配置
- R で回転
- 解体時 80% 素材返却
- ブロック破壊時ドロップなし

### 建設時の制約

建設メニューから配置した場合のみ WR01 を正規設備として生成する。

通常のブロック設置で自由に増殖できる仕様にはしない。

## constraints

### サーバー処理

WR01 のリンク探索・送電判定はサーバー側で行う。

クライアント側は、

- リンクの存在
- 接続先座標
- 送電状態

を受け取り、発光線を描画する。

### Tick 頻度

送電処理:

- **20 tick = 1秒に20回**

ただし、毎 tick に全候補探索を行わない。

リンク探索:

- 設置時
- 破壊時
- リンク切断時
- **20 tick に1回の再探索**

程度とする。

既存のリンクが正常な場合、毎 tick の距離探索・近傍探索は行わない。

### 描画距離

発光線は最大:

**96ブロック**

まで描画する。

送電リンク自体は128ブロックまで成立する。

したがって、

- 96ブロック以内: 発光線表示
- 97～128ブロック: 無線接続は成立するが発光線は表示しない

とする。

これにより遠距離リンクによる大量の長い線の描画負荷を抑える。

設定値は将来的に Config 化できる構造にする。

### チャンク

リンク先のチャンクを、WR01 のためだけに常時ロードしない。

チャンクがアンロードされた場合:

- 送電停止
- リンク状態を一時停止
- クライアント側の発光線を非表示

とする。

チャンクロードを強制する Chunk Ticket は使用しない。

### ネットワーク

WR01 の発光線描画情報を毎 tick 全クライアントへ送信しない。

以下の場合だけ同期する。

- WR01 設置
- WR01 破壊
- リンク確立
- リンク切断
- 送電状態の大きな変化

送電量の細かな変動はクライアントへ同期せず、発光線アニメーション側で補間する。

### 無線ネットワークのループ

`A → B → A` のような循環自体は禁止しない。

ただし、同一 tick 内で FE が無限に循環しないよう、

**1 FE は同一送電処理内で同一 WR01 を2回以上通過しない**

ようにする。

また、ネットワーク全体を再帰的に探索して「最終目的地」まで送電する実装は禁止する。

送電は必ず1リンク単位で処理する。

### 発光線の描画

発光線はブロックとして存在しない。

- 衝突なし
- 当たり判定なし
- 採掘不可
- 光源ブロックとしての明るさなし
- 水中でも表示可能
- 壁や地形を貫通して表示可能

とする。

これは「無線」の表現であるため、視線遮蔽を考慮しない。

## accept

以下をすべて満たした場合、WR01 実装を合格とする。

### 配置

- [ ] 建設メニューの「設備」に `無線送電中継器` が存在する。
- [ ] ホログラム配置ができる。
- [ ] R で回転できる。
- [ ] 解体時に素材の80%が返却される。
- [ ] 通常破壊でブロックがドロップしない。
- [ ] 拠点外の海底にも設置できる。
- [ ] 殻ブロックへの接触を必須条件としない。

### リンク

- [ ] 128ブロック以内の WR01 を自動検出できる。
- [ ] 最大2リンクまで確立できる。
- [ ] 128ブロックを超える WR01 とは接続しない。
- [ ] 視線・水・地形によってリンクが遮断されない。
- [ ] リンク先が破壊・アンロードされた場合に送電停止する。
- [ ] 条件回復後に自動再接続できる。

### 送電

- [ ] WR01 が Forge `ENERGY` capability として動作する。
- [ ] 拠点の HabitatPower と接続できる。
- [ ] WR01 間で双方向送電できる。
- [ ] 1リンク最大512 FE/tである。
- [ ] 距離に応じて100% / 90% / 80% / 70%の効率になる。
- [ ] 損失分の FE が消費される。
- [ ] WR01 が大容量蓄電器として利用できない。
- [ ] 多段中継が可能である。
- [ ] 無限ループによる FE 増殖・無限処理が発生しない。

### 表示

- [ ] スニーク右クリックで接続状態を確認できる。
- [ ] 未リンク時はアンテナが弱く発光する。
- [ ] リンク中はアンテナからアンテナへ青緑色の発光線が表示される。
- [ ] 発光線は水中でも表示される。
- [ ] 送電中は発光線が明るくなる。
- [ ] 送電方向に沿って光が流れる。
- [ ] 発光線は最大96ブロックまで表示される。
- [ ] 96～128ブロックのリンクは送電可能だが発光線を表示しない。
- [ ] 発光線が物理ブロックとして存在しない。

### 性能

- [ ] リンク探索を毎 tick 実行しない。
- [ ] 正常リンクの維持に近傍全探索を毎 tick 必要としない。
- [ ] WR01 のためだけにチャンクロードを強制しない。
- [ ] 発光線情報を毎 tick 大量にネットワーク同期しない。
- [ ] 多数設置してもサーバー tick を大きく阻害しない。

### ゲームデザイン

- [ ] 工業ケーブルの128/512 FE/tという既存仕様と競合しない。
- [ ] WR01 は「長距離・便利だが損失と距離制限がある」という位置づけになっている。
- [ ] HabitatPower の1,000,000 FE共有バッファ仕様を変更しない。
- [ ] 既存の拠点発電機（海流タービン・地熱・バイオ燃料）をそのまま無線送電へ接続できる。
- [ ] WR01 の追加によって既存拠点の FE 配電ルールを変更する必要がない。
