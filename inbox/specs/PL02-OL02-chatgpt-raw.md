# PL02 プランターの作り直し
tier: standard

files:
- `hydro_planter` の Block / BlockEntity / renderer・model 関連実装
- `hydro_planter` の登録・レシピ・loot / blockstate / model / texture 関連データ
- 既存 GUI / Menu / Screen 関連実装（不要化）
- 必要に応じて `Abyssia` の Forge 1.20.1 / NeoForge 1.21.1 共通実装・各ローダー差分
- 新規テクスチャ一式

goal:
- 既存の `hydro_planter` を、**高さ 8px の下側ハーフブロック形状**のシンプルな水耕プランターへ作り直す。
- 1ブロック内を 2×2 の4区画として扱い、**1つのプランターに最大4株**を植えられるようにする。
- 専用GUIを廃止し、**右クリックした位置の区画を対象に直接植える・収穫する**操作へ変更する。
- 既存3作物の種類と基本成長時間・収穫物は維持する。
  - `abyssal_mushroom` → `mushroom_cap` 1～2、8分
  - `pressure_gourd` → `gourd_flesh` 1～2、12分
  - `deep_kelp` → `kelp_leaf` 2～3、6分
- 収穫後はその区画を空き状態に戻し、再び植えられるようにする。
- プランター本体は隣接しても**枠が自動連結しない単体形状**とする。
- 成長状態をワールド上で視認できるようにし、4区画それぞれの状態を独立して表示する。
- 既存の「水・FEを消費しない」「BlockEntityによる時間管理」という設計は維持する。
- 完成後も自動搬出に対応できるよう、**ホッパーによる収穫物搬出を維持**する。BlockEntity のアイテムハンドラーを利用した搬出方式を前提とする。ForgeではBlockEntityに `IItemHandler` を公開する設計が標準的。

constraints:
- 本体形状は **下側ハーフブロック、厚さ8px**。通常のフルブロックにはしない。
- 4区画は以下の固定配置とする。

  ```
  ┌─────┬─────┐
  │  NW │  NE │
  ├─────┼─────┤
  │  SW │  SE │
  └─────┴─────┘
  ```

- 右クリック位置から、クリックした水平位置に対応する区画を判定する。
  - X/Z の中央線を境界とする。
  - ブロック外周や境界付近では、実際の `BlockHitResult` のローカル座標を用いて安定して判定する。
  - クリックした区画だけを操作対象とし、他の3区画には影響を与えない。
- **植える操作**
  - 空いている区画を対象に、対応する種・苗アイテムを持って右クリックすると植える。
  - 1回の右クリックで1区画だけ植える。
  - 既に植物がある区画には植えられない。
  - 水入りバケツ等を要求しない。
- **収穫操作**
  - 成長完了した区画を空手、または通常の右クリック操作で対象にして収穫できる。
  - 未成熟状態では収穫処理を実行しない。
  - 収穫物をプレイヤーへ直接付与するのではなく、**プランターの搬出インベントリへ格納**する。
  - 搬出インベントリが満杯の場合は、収穫を失敗させてアイテムを消失させない。
  - 収穫成功後、その区画だけ空状態へ戻す。
  - 可能なら収穫時に種・苗を消費する現在仕様を維持する。
- 4区画それぞれについて、少なくとも以下の状態を保存する。
  - 空
  - 作物種別
  - 成長開始時刻または残り成長時間
  - 成長段階
- 成長時間はワールド時間ベースで管理し、サーバー再起動・チャンクアンロード後も進行状態が破綻しないようNBTへ保存する。
- 成長段階は最低でも **植えた直後 → 中間成長 → 成長完了** の3段階を視覚的に区別する。作物ごとに形状が違って見えることが望ましい。
- 4区画の植物は、それぞれ独立した位置に表示する。植物モデルが隣の区画へ侵食しないようにする。
- 既存の multipart の連結枠システムは廃止する。**隣接プランター同士は単純に個別の8pxハーフブロックとして並ぶ**。
- GUI / Menu / Screen は不要。既存GUIを開く右クリック処理がある場合は削除または新しい区画操作へ置換する。
- 既存 `hydro_planter` の登録名を可能な限り維持し、既存ワールドとの互換性を優先する。
- 旧BlockEntityに4区画以外の旧データが存在する場合は、以下の移行方針とする。
  - 旧プランターの苗スロットに植えられていた植物 → **NW区画へ移行**
  - 旧収穫物スロットの未搬出アイテム → 新しい搬出インベントリへ移行
  - 旧成長時間 → NW区画の成長状態へ可能な限り引き継ぐ
  - 旧データを読み込めない場合でも、ブロック破壊時に旧アイテムを黙って消失させない
- ただし、旧データ構造を安全に判別できない場合は、**無理な自動変換よりアイテム消失防止を優先**する。
- レシピは既存 `hydro_planter` の材料・作成難度を原則維持し、形状変更だけを理由にゲームバランスを変更しない。
- テクスチャは新規作成する。
  - 本体：8pxハーフブロックとして認識できる深海基地向けデザイン
  - 上面：4区画が視覚的に分かる程度の植栽スペース
  - 側面：8px厚の構造体として自然に見える
  - 隣接しても連結枠に見えない
  - Vanilla Minecraft 1.20.1風の16pxピクセルアート
  - NeoForge 1.21.1でも同じデザイン思想を使用
- 必要なテクスチャは少なくとも以下。
  - `hydro_planter` 本体上面
  - `hydro_planter` 側面
  - `hydro_planter` 底面または必要な面
  - `abyssal_mushroom` 成長段階3種
  - `pressure_gourd` 成長段階3種
  - `deep_kelp` 成長段階3種
- 植物テクスチャは透明背景を利用し、Minecraftの植物モデルとして自然に見えるものとする。
- Forge 1.20.1 と NeoForge 1.21.1 の両方で同一のゲーム仕様になるようにする。ただしAPI差分による登録・Capability・レンダリング実装差は各ローダー側で適切に吸収する。BlockEntityは動的データやtick処理に利用でき、1.20.1ではBlockEntityTypeのBuilderによる登録が前提となる。
- サーバー権威で状態を管理し、クライアント側は表示だけを同期する。
- 4区画の状態変更時にBlockEntityをdirtyとして保存対象にする。

accept:
- [ ] `hydro_planter` が高さ8pxの下側ハーフブロックとして表示される。
- [ ] 隣接しても既存のmultipart連結枠が発生しない。
- [ ] 1ブロックに4区画が存在する。
- [ ] 4区画へ同時に別々の植物を植えられる。
- [ ] 右クリックした区画だけが操作対象になる。
- [ ] 空区画への右クリック＋対応苗で植え付けできる。
- [ ] 専用GUIが開かない。
- [ ] 成長時間が3種とも既存仕様どおり8分 / 12分 / 6分。
- [ ] 3段階以上の成長状態がワールド上で視認できる。
- [ ] 4区画の植物が互いに重ならず、それぞれの区画内に表示される。
- [ ] 成長完了した区画を右クリックして収穫できる。
- [ ] 収穫した区画だけが空になる。
- [ ] 未成熟の植物を誤って収穫して消失させない。
- [ ] 搬出インベントリへ収穫物が入り、ホッパーで搬出できる。
- [ ] 搬出先が満杯でも収穫物が消失しない。
- [ ] サーバー再起動・チャンク再読み込み後も4区画の植物と成長状態が維持される。
- [ ] 旧 `hydro_planter` の既存データを可能な範囲で新形式へ移行できる。
- [ ] 旧GUI関連コードが通常操作経路に残っていない。
- [ ] レシピが従来どおり使用できる。
- [ ] Forge 1.20.1 / NeoForge 1.21.1 の双方で同じゲームプレイ仕様になる。


# OL02 油昆布の油嚢を発光
tier: light

files:
- `oil_kelp` Block / BlockEntity / Plant関連実装
- `oil_sac` のモデル・テクスチャ関連
- `oil_kelp` の成長・熟成状態表示関連
- 必要に応じて Forge 1.20.1 / NeoForge 1.21.1 の発光・光源関連実装
- `oil_sac` / 油嚢部分の新規エミッシブテクスチャ

goal:
- `oil_kelp` が熟成して油嚢を形成した状態で、**油嚢そのものが淡く発光する**ようにする。
- 深海で視認性を高めつつ、強すぎる照明にならない程度の自然な生物発光とする。
- 油嚢は既存どおり `oil_kelp` モデルの一部として表示し、収穫時には `oil_sac` を落とす。
- 発光は通常の未熟成油昆布には適用せず、**油嚢が存在する状態だけ**に限定する。

constraints:
- 発光状態は **油嚢がモデル上に表示される熟成状態のみ**。
- 油嚢の光レベルは **4** とする。
  - 深海で「光っている」と明確に分かる。
  - シーランタン等の強力な照明設備の代替にはならない。
- 発光色は **暖色寄りの黄緑～琥珀色**とする。
  - 油を含んだ生体器官らしい色。
  - 通常の海草の緑とは明確に区別する。
- 見た目としては油嚢の内部が淡く輝いているようにする。
- エミッシブ表現を採用し、油嚢部分だけが通常テクスチャより明るく見えるようにする。
- エミッシブテクスチャは通常テクスチャとは分離する。
  - 通常テクスチャ：油嚢の立体・色・陰影
  - エミッシブ：発光させる油嚢内部のピクセル
- 発光テクスチャは黒背景ではなく、**発光対象部分を明示できる専用マスク**として扱う。
- 発光部分に通常テクスチャの明暗情報を混ぜすぎず、エミッシブ時に明瞭な光点として見えるようにする。
- Iris / Oculus 等のシェーダー環境でも、可能な範囲でエミッシブ部分が発光して見えることを確認する。
- ただし、外部シェーダーの独自Bloomや発光処理をMod側から強制しない。
- **光源としての光レベル4**と**見た目のエミッシブ表現**を分離して考える。
  - 光源処理が利用できる場合は周囲を実際に照らす。
  - エミッシブ処理が利用できない環境でも、油嚢のテクスチャ自体が明るく見えるようにする。
- シェーダーOFFでも基本的な発光表現が成立すること。
- Iris/Oculus使用時に、油嚢が真っ黒になったり通常部分まで発光したりしないこと。
- 光源ブロック化によって油昆布の成長・破壊・再生処理を壊さない。
- 油嚢を収穫した場合は、当然ながらその位置の発光も消える。
- 油昆布本体全体を発光させない。**発光対象は油嚢だけ**。
- 必要なテクスチャは最低限以下。
  - `oil_kelp` 通常テクスチャ（必要なら現行を微調整）
  - `oil_sac` 通常テクスチャ
  - `oil_sac_emissive` エミッシブマスク
- 新規エミッシブテクスチャは16×16のVanilla Minecraft風ピクセルアートとして作成し、油嚢の輪郭・形状と完全に対応させる。
- NeoForge 1.21.1では発光・BlockEntity/Block側APIがForge 1.20.1と異なる場合があるため、共通仕様として「油嚢のみ・光レベル4・シェーダー非依存の基本視認性」を維持し、実装APIは各ローダーに合わせる。
- 発光のためだけに毎tickで周囲の大量のブロックを更新するような重い実装は避ける。
- 大量の油昆布を設置した場合でも、光源更新による負荷が過大にならない設計を優先する。

accept:
- [ ] 未成熟の `oil_kelp` は発光しない。
- [ ] 油嚢が付いた熟成状態では油嚢部分だけが発光する。
- [ ] 発光部分が黄緑～琥珀色の生物発光として視認できる。
- [ ] 光レベル4として周囲を淡く照らす。
- [ ] 油昆布本体全体が発光する状態になっていない。
- [ ] 油嚢を収穫すると該当箇所の発光が消える。
- [ ] `oil_sac` の通常テクスチャとエミッシブマスクが正しく対応している。
- [ ] シェーダーOFFでも油嚢が明るく見える。
- [ ] Iris/Oculus使用時でも油嚢の発光が破綻しない。
- [ ] シェーダーのBloom等がなくてもゲームプレイ上の発光が確認できる。
- [ ] 既存の油昆布の成長・収穫・再生処理に影響しない。
- [ ] 油嚢のない状態に不要な光源処理が残らない。
- [ ] Forge 1.20.1 / NeoForge 1.21.1 の双方で同じ発光仕様になる。
