This is a read-only audit of the committed HEADs. Uncommitted working-tree changes (RS01 in progress) are ignored.

## 2. Real gaps

| # | File / feature | What differs | Behind |
|---|---|---|---|
| G1 | CU01 `environment/OceanCurrentPush.push` / `onLevelTick` (config interaction) | **Forge:** `ocean_current.push_entities=false` also switches off CU01 stream push for all server-side entities, because the level-tick gate returns early. On the client, `ocean_current.push_players=false` (OceanCurrentClient) also stops CU01 push for the player, whatever `current_streams.affects_players` says. **Neo:** streams are gated only by `current_streams.affects_*`, and push_players/push_entities gate only the legacy field and natural currents. Smaller differences: Forge applies the 0.60 combined cap when only a natural current pushes, Neo only when a CU01 band is involved. Exposure (CurrentResistant) scales the band's target speed on Forge but the band delta on Neo | **Forge** (Neo matches the config comments). Defaults are equal, so this only shows when configs are edited |
| G2 | CU01 client streaks: `client/CurrentStreamClient` + `CurrentStreamParticle` (Forge) vs `CurrentParticle` stream mode (Neo) | The two were implemented in parallel and the LOD details differ. Forge: count lerps continuously with distance (160→80→30→10) × strength, release span ±(32+d) blocks, mid/far streaks get +0.5 length. Neo: per-band step count, lerped by strength (80–160 / 30–80 / 10–30), span ±40/±64 blocks, separate mid/far width/length ranges, budget split per band. Streams look similar but not identical | Design divergence; pick one as canonical |
| G3 | CU01 F3 debug text (`CustomizeGuiOverlayEvent.DebugText`: "Current stream: tier strength r flow dir streaks") | Present only on Neo (in CurrentStreamClient) | **Forge** |
| G4 | ClientConfig `current_streams.max_render_distance` | Range is 16..160 on Forge and 0..160 on Neo (Neo treats 0 as off). Default 96 on both | Minor; align |
| G5 | Config `current_streams.min_length/max_length/min_width/max_width` | DoubleValue on Forge (64.0…), IntValue on Neo (64…). Same defaults and ranges. Neo also sorts min/max when they are swapped; Forge does not | Minor; align types |
| G6 | lang en_us/ja_jp: `container.abyssia.hydro_planter`, `gui.abyssia.hydro_planter.{empty,growth,ready}` | Removed on Forge by PL02 (8ddc553). Still present on Neo (1240 vs 1236 keys) but referenced nowhere, so stale | **Neo** (remove the 4 keys) |
| G7 | `data/minecraft/tags/worldgen/world_preset/normal.json` (`abyssia:ocean_world`) | Neo only, left over from the initial commit. Forge has no such tag | **Neo** (probably stale; check whether it is intended) |
| G8 | Tooling, not the mod: `tools/agentflow/hook.py`, `tools/blockbench-mcp/README.md`, `.claude/agents/verify.md`, `.claude/settings.json` | Forge only. `tools/agentflow/server.py` (726 vs 560 lines), `flow.py`, `index.html` and `autorun.json` are older on Neo | **Neo** (only matters if agentflow is run from the Neo worktree) |

Same feature, different structure (not a gap): Forge has `CurrentStreamCommand` (`/abyssia currents streams near|show`), while Neo puts the same subcommands into `NaturalCurrentCommand`. Neo's `CurrentStream` pre-samples a polyline where Forge evaluates the spline analytically. The network salt packet carries the same 10 stream params on both sides.

## 3. Expected differences (noted, not problems)

- Loader APIs: events, DeferredRegister types, capabilities→`EnergyHooks`, payloads, `ModDataComponents` (energy, habitat_dist/mode/rot), `PropulsionScrewPose` (1.21 arm-pose hook).
- EN01: Forge `enchantment/*Enchantment.java` vs Neo `data/abyssia/enchantment/*.json` plus the `exclusive_set`, `enchantable/thermal_catch` and `minecraft:tags/enchantment/*` tags. deep_swimmer is an attribute effect on Neo and an EffectEvents modifier on Forge.
- 1.21 data folders and shapes (via tools/mc_format.py): recipe JSON `id`, loot `predicates`, and `uniform` int providers. Also `dimension_type` `monster_spawn_light_level`.
- `forge_data` → `neoforge_data` in 56 models. `#forge:shears` → `#c:tools/shear`. `forge:rods/wooden` → `c:rods/wooden`. `data/c/tags/{blocks,items}` → `{block,item}`.
- `deep_fissure` / `twilight_reef` biomes: Neo has one extra vanilla feature, `minecraft:ore_diamond_medium`. gen_worldgen copies the vanilla feature list from the 1.21.1 jar.
- `shaders/core/shader_fog_composite.json`: no `blend` on Neo, because 1.21 core shader JSON dropped it. Blending is set in ShaderFogPass instead.
- META-INF: mods.toml vs neoforge.mods.toml, accesstransformer.cfg, enumextensions.json. `tools/mc_format.py` is Neo only. PROTOCOL numbers differ.
- `ModTools` armor: Forge `AlloyArmor` class vs Neo registered `ArmorMaterial` with `getDurability(30)` (same numbers).
